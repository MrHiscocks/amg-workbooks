From interface to complete program

Larger interfaces separate events, data and display updates into purposeful functions.

Events

Event-driven execution

Setup code creates the interface once. Command functions run later when the user clicks a button or changes a control.

def addItem():
    # Runs after the Add button is clicked
    item = itemEntry.get()
    basket.append(item)
    updateDisplay()
Structure

Multiple command functions

Give each button one clear job. Small functions are easier to test and make change requests safer.

    ...

    ...

    ...
Layout

Frames and interface areas

A Frame groups related widgets. This makes layout clearer and allows one part of the interface to be updated or hidden together.

inputFrame = tk.Frame(window)
inputFrame.pack(fill="x", padx=12, pady=8)

resultsFrame = tk.Frame(window)
resultsFrame.pack(fill="both", expand=True)
Lists

Displaying list data

Keep the data in a Python list and rebuild the display after a change. A Listbox can show several stored values.

players = ["Alex", "Sam", "Taylor"]

def refreshPlayers():
    playerList.delete(0, tk.END)
    for player in players:
        playerList.insert(tk.END, player)
Records

Records and selection

A dictionary stores named fields for one record. Use an identifier from an Entry or selected list item to find the correct record.

player = {"id": "P104", "name": "Alex", "score": 18}
nameLabel.config(text=player["name"])
scoreLabel.config(text=str(player["score"]))
Files

Loading and saving data

Load data before the interface is used, update the in-memory collection, then save after a confirmed change. Keep file operations in separate functions.

def saveSettings():
    with open("settings.txt", "w") as file:
        file.write(themeEntry.get())
    feedbackLabel.config(text="Settings saved")
Keep one source of truth

Store the real data in lists or records. Widgets display or collect values, but they should not become the only place where important data exists.

FAULTY PYTHON
01

Display refresh fault

New names are added to the list, but the Listbox never changes.

Success checks

  • Adding a name updates both the list and Listbox
  • The Entry is cleared after a successful add
Call refreshNames() at the end of addName(), then use nameEntry.delete(0, tk.END).
FAULTY PYTHON
02

File save fault

Only the final player is stored because the file is reopened incorrectly.

Success checks

  • Every player is written to the file
  • The file is opened once for the complete save operation
Open the file before the loop. Indent the for loop inside the with block.
