02

The development process

Good development decisions are recorded before, during and after implementation.

Investigate

Investigate requirements

Identify the user, the problem and what the finished system must do. Functional requirements should be specific and testable.

Requirement: The system must calculate
and display the total booking cost.
Analyse

Inputs, processes and outputs

Separate what enters the system, the operations performed and what the user receives. This exposes missing data and unclear rules.

Input: ticket quantity
Process: quantity × ticket price
Output: formatted total cost
Design

Decomposition and pseudocode

Break the problem into manageable functions. Use pseudocode to describe logic without becoming distracted by exact Python syntax.

FUNCTION calculateTotal(quantity, price)
    total = quantity * price
    RETURN total
END FUNCTION
Design

Interface and data design

Sketch the controls, labels and feedback the user needs. Choose data structures that match the required records and operations.

event = {
    "id": "E04",
    "name": "Community Run",
    "spaces": 45
}
Test

Test plans

Choose typical, boundary, extreme and erroneous data. Record the input, expected result, actual result and whether the test passed.

Input: quantity = 1
Type: boundary
Expected: booking accepted
Actual: booking accepted
Result: Pass
Review

Refinement and evaluation

Use failed tests and user feedback to make controlled improvements. Evaluate the final system against each requirement using evidence.

Requirement met: Yes
Evidence: Boundary tests 2 and 3 passed.
Refinement: Clearer error message added.
Evidence matters

A claim such as “the program works” is too vague. Refer to a requirement, test result or observed interface behaviour.
